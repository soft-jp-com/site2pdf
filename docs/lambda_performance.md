# site2pdf Lambda 版の性能測定記録

AWS Lambda（東京リージョン ap-northeast-1、x86_64、メモリ 2048MB）で測った結果の記録。
すべて国税庁トップ（`https://www.nta.go.jp/`）を `outputs: ["json","screenshot"]`（一部は旧 `format: json`）で取得した値。
値は CloudWatch Logs の REPORT 行と、アプリのログ（`lambda.prefetch`、`chrome.launch_headless`、`cdp.process_start`）から取った。

## 用語

- **コールドスタート**: 新しい実行環境で最初に処理する呼び出し。イメージを差し替えた直後の1回目は、AWS 側にイメージのキャッシュがない「本当のコールドスタート」になる。
- **Chrome の起動**: `chrome.launch_headless` から `cdp.process_start` まで（Chrome を起動して CDP で接続できるまで）。
- **課金時間**: REPORT 行の Billed Duration。SnapStart 以外のコールドスタートでは初期化（Init）も含まれる。

## SnapStart の検証（検証用関数 `site2pdf-snapstart-test`）

- イメージ: `snapstart-a34d1f3`（ブランチ `archive/snapstart`、コミット `a34d1f3`）
  - 初期化で先読みを最後まで行い、**Chrome を1回起動して日本語ページを開いてから終了**し、`/runtime/restore/next` でスナップショットを取る版。先読みだけの版は測っていない。
- 設定: メモリ 2048MB、タイムアウト 120秒、ephemeral storage 512MB、`SnapStart.ApplyOn=PublishedVersions`、環境変数は本番と同じ（起動待ち 30秒、先読み予算 7000ms。SnapStart 時の先読みは既定 60秒）
- `publish-version` からスナップショット完成（バージョンが Active）まで: 約85秒
- バージョン 1 を指定して3件を同時に呼び出し、3回とも別の実行環境で復元された（2026-09-27 12:45 JST）。

| 呼び出し | Restore Duration | Chrome の起動 | Duration | 課金時間 | 課金される復元時間 | Max Memory |
|---|---|---|---|---|---|---|
| 1 | 948.80ms | 0.18秒 | 4,561ms | 4,563ms | 1ms | 835MB |
| 2 | 861.02ms | 0.21秒 | 4,658ms | 4,660ms | 2ms | 837MB |
| 3 | 1,024.14ms | 0.16秒 | 4,061ms | 4,064ms | 2ms | 836MB |

3件とも成功（タイトル「国税庁」、スクリーンショット2枚）。クライアントから見た所要時間は 6.1〜6.6秒。

### 本番（`f738dd2`）との比較

| | 本番 `f738dd2`（コールド） | SnapStart（復元） |
|---|---|---|
| 初期化／復元 | Init 7,843ms | Restore 約0.9秒 |
| Chrome の起動 | 約1.9秒 | 約0.2秒（ウォームとほぼ同じ） |
| Duration | 6,341ms | 4,061〜4,658ms |
| 課金時間 | 14,185ms | 4,064〜4,660ms（＋復元 1〜2ms） |

SnapStart はコールドスタートをウォーム時とほぼ同じ速さにした。ただし次の費用と手間がかかるため、本番には入れないと判断した（2026-09-27）。

- スナップショットの保持料（公開したバージョンごと、メモリ量に比例、最低3時間分）と復元料がかかる。
- 呼び出しは公開済みバージョンかエイリアス経由に限られ、コード更新のたびに `publish-version` とエイリアスの付け替えが要る。
- ephemeral storage を 512MB 以下にする必要がある。

### 検証時の注意

- 手元の AWS CLI 2.7.35 は `--snap-start` に対応していなかったため、`uv run --no-project --with awscli python -m awscli`（awscli 1.46.1）で関数の作成とバージョンの公開を行った。
- 検証用関数 `site2pdf-snapstart-test` は検証後に削除する（保持料を止めるため）。

## 確認していないこと

- 長時間呼ばれなかった後のコールドスタート
- 大量に同時呼び出ししたときの挙動
- SnapStart の東京リージョンでの単価
